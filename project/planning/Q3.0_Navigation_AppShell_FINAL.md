## Overview

This specification defines the complete navigation structure and app shell for WeightGPT after onboarding completion. The app features a 3-tab bottom navigation design with Home as the central hub (80% user time), Log for quick tracking, and Progress for analytics.

### Design Philosophy
- **Modern & Clean:** Predominantly white backgrounds with strategic pops of color
- **Context-Aware:** Different color palettes for Nutrition (warm) vs Workout (cool) contexts
- **Minimal Friction:** Quick-log checkboxes, AI-powered text logging, one-tap actions
- **Goal-Oriented:** All features align with user's weight/fitness goals from onboarding

### Key Features
- Dual-mode Home tab (Nutrition ⟷ Workout toggle)
- AI-powered natural language logging
- Visual progress tracking (Russian doll circles for nutrition, segmented circle for workouts)
- Comprehensive history and favorites management
- Weekly planning with grocery list integration
- Streak tracking and gamification
- Goal-based workout/meal personalization

### Structure
```
┌─────────────────────────────────────┐
│                                     │

│                                     │
├─────────────────────────────────────┤
│   🏠 Home    ➕ Log    📊 Progress  │

```

### Tabs

**1. Home Tab**
- **Icon:** House icon 🏠
- **Active State:** Filled icon + accent color (context-dependent: amber for Nutrition, blue for Workout)
- **Purpose:** Today's hub - view meals/workouts, quick-log checkboxes, progress tracking
- **Default View:** Nutrition (remembers last toggle state)

**2. Log Tab**
- **Icon:** Plus sign ➕ in circle
- **Active State:** Filled icon + accent color
- **Purpose:** Manual logging hub - AI-powered text entry for meals/workouts/weight
- **Default View:** Quick action buttons with "All" filter selected

**3. Progress Tab**
- **Icon:** Chart/graph icon 📊
- **Active State:** Filled icon + accent color
- **Purpose:** Analytics hub - weight tracking, weekly summaries, streaks, history
- **Default View:** Scrollable page starting with weight graph

### Behavior
- **Persistence:** Bottom nav visible on all main screens (Home, Log, Progress)
- **Hidden On:** Modal overlays, detail views (slides over nav), onboarding
- **State Memory:** Each tab remembers scroll position and view state when switching
- **Tap Active Tab:** Scrolls to top of current view

- Circles: Fully filled, vibrant colors

*Exceeded State (Over Target):*
- Circles: Fill beyond 100% (use warning color #F05D5E)

#### Interactions

**Tap Checkbox (○/●):**
- **If unchecked (planned meal):** Quick-log meal
  - Checkbox animates to filled (●)
  - Badge "Logged" appears
  - Timestamp added
  - Progress circles update immediately
  - Success haptic feedback
- **If checked (logged meal):** Unlog meal (with confirmation)
  - Modal: "Unlog this meal?"
  - Buttons: [Cancel] [Unlog]
  - If confirmed: Reverts to unchecked state, removes timestamp
  - Progress circles update immediately

**Replacement Logic (Checkbox vs AI Logging):**
- **Scenario:** User quick-logs breakfast via checkbox, then uses AI Log tab to log a custom breakfast
- **Behavior:** AI logging flow detects existing breakfast entry and shows 3-option prompt: "You already logged breakfast today. What would you like to do?"
  - **"Replace existing"**: Removes first breakfast, adds new one (single breakfast remains)
  - **"Add as new"**: Keeps both entries (allows multiple breakfasts - e.g., user had 2 breakfasts)
  - **"Cancel"**: Discards new entry, keeps original
- **Priority:** Most recent entry determines which meal card shows "Logged" badge on Home tab
- **Totals:** All logged entries count toward daily calorie/macro totals

**Heart Icon (Top-Right Corner):**
- Small heart icon ♡ appears on every meal card (top-right corner, 20px)
- **Unfavorited state:** Empty/outline heart ♡ (#C7C7CC gray)
- **Favorited state:** Filled heart ♥ (#FF6B6B coral red)
- **Tap to favorite/unfavorite:** Single tap toggles state
- Shows toast: "Added to favorites! ❤️ [Undo]" or "Removed from favorites"
- Makes feature more discoverable than gesture-only

**Tap Arrow (→) / Tap Card Body:**
- Navigate to Meal Detail screen (see Meal Detail section)
- Slide-in transition from right

**Long-Press OR Swipe Right on Card (Alternative Actions):**
- Quick actions slide-out menu:
  ```
  [❤️ Favorite] [👎 Dislike] [🗑️ Delete]
  ```
- **Favorite:** Same as heart icon tap (power-user alternative)
- **Dislike:** Marks for AI avoidance in future plans
- **Delete:** Only for logged custom meals (shows confirmation modal)

```javascript
// Pseudocode for dismissal learning
function shouldShowNudge(nudgeType, userHistory) {
  const recentDismissals = userHistory.getConsecutiveDismissals(nudgeType);

  if (recentDismissals >= 7) {
    // User clearly doesn't want this nudge
    return false; // Suppress for 1 week
  }

  if (recentDismissals >= 3) {
    // User sometimes dismisses
    const dayOfWeek = getCurrentDayOfWeek();
    return dayOfWeek % 2 === 0; // Show every other day
  }

  return true; // Show normally
}
```

## AI Integration

### OpenAI API Usage

**Endpoints:**
1. **Meal Logging (Text Parsing)**
   - Input: User's meal description text
   - Output: Parsed food items, quantities, calories, macros
   - Model: GPT-4o-mini (cost-effective)
   - Max tokens: 500

2. **Follow-Up Questions**
   - Input: Parsed meal + ambiguities
   - Output: Clarifying questions (multiple choice when possible)
   - Model: GPT-4o-mini
   - Max tokens: 200

3. **Workout Logging (Text Parsing)**
   - Input: User's workout description
   - Output: Parsed workout type, duration, exercises, calories
   - Model: GPT-4o-mini
   - Max tokens: 400

4. **Meal Generation (Alternatives)**
   - Input: Current meal macros, dietary restrictions, available ingredients, user preferences
   - Output: 3 alternative meal options with recipes
   - Model: GPT-4 (better creativity)
   - Max tokens: 1500

5. **Workout Generation (Alternatives)**
   - Input: Current workout type, duration, equipment, user goal, fitness level
   - Output: 3 alternative workout options
   - Model: GPT-4
   - Max tokens: 1200

6. **Weekly Insights**
   - Input: User's weekly activity data (meals logged, workouts, patterns)
   - Output: 1-2 sentence personalized insight
   - Model: GPT-4o-mini
   - Max tokens: 100
   - Frequency: Once per week (cached for 7 days)

### Nutrition Validation

**Calorie Sanity Checks:**
AI-generated nutrition data must pass validation before showing to user. If values fall outside reasonable ranges, show warning modal.

**Validation Ranges by Meal Type:**
- **Breakfast:** 150-800 cal
- **Lunch:** 300-1200 cal
- **Dinner:** 300-1500 cal
- **Snack:** 50-400 cal

**Out-of-Range Behavior:**
If AI returns calories outside expected range:
1. Show warning modal:
   ```
   ⚠️ Unusual Calorie Estimate

   This seems unusually [high/low] for [meal type].
   The AI estimated [X] calories.

   Please verify this is correct or edit manually.

   [Edit Manually]  [Accept Anyway]  [Cancel]
   ```
2. Log confidence score to backend for analysis
3. User can override or edit before confirming

**Macro Validation:**
- Protein: 0-200g per meal
- Carbs: 0-300g per meal
- Fat: 0-150g per meal
- If macros don't sum to within ±50 calories, flag for review

### Caching Strategy

**Cache Duration:**
- Weekly insights: 7 days
- Generated meal alternatives: 24 hours (same request)
- Parsed meal descriptions: 1 hour (if user re-logs similar meal)

**Cache Keys:**
- Meal parsing: Hash of user input + dietary restrictions
- Meal generation: Hash of current meal + constraints
- Insights: User ID + week number

### Error Handling

**API Timeout:**
- Timeout: 10 seconds
- Fallback: "Taking longer than expected. Try again?"
- Retry: Up to 2 attempts

**API Rate Limit:**
- Show: "Too many requests. Please wait a moment."
- Implement: Exponential backoff (2s, 4s, 8s)

**Invalid Response:**
- Parse error → Show manual entry form
- Missing data → Ask user to fill in gaps

**Onboarding Generation Failures (Q1 Loading Break 3, Q2 Meal Generation):**
- Timeout after 30 seconds without response

  ```

  [Try Again]  [Skip for Now]
  ```
- Both buttons shown immediately at 30 seconds
- If user selects [Try Again]: Retry API call (up to 3 total attempts)
- If user selects [Skip for Now]:
  - Continue to next step (paywall for Q1, or workout generation)
  - Content generates in background after subscription/completion
  - Push notification when ready: "Your [meal plan/workout plan] is ready!"
- **Applies to:** Q1 workout generation, Q2 meal plan generation, Q3.0 weekly planning

### Token Budget

**Monthly Budget:** 1M tokens (estimated for 1000 users)

**Per-User Limits:**
- Meal logging: ~100 tokens/meal × 3 meals/day = 300 tokens/day

- **Total per user:** ~12,000 tokens/month

**Optimization:**

- Use GPT-4 only for creative generation

## Backend Logic

### User Goals & Personalization

**Goal Types (from Q1 Onboarding):**
1. **Weight Loss**
   - Calorie deficit: -500 cal/day from TDEE
   - Workout mix: 60% cardio, 40% strength
   - Meal focus: High protein, moderate carbs

2. **Weight Gain / Muscle Building**
   - Calorie surplus: +300 cal/day from TDEE
   - Workout mix: 70% strength, 30% cardio
   - Meal focus: High protein, high carbs

3. **Maintenance**
   - Calorie target: TDEE
   - Workout mix: 50% strength, 50% cardio
   - Meal focus: Balanced macros

**Adaptive Adjustments:**
- If user consistently under/over logs, suggest target adjustment
- If user favorites certain meals, increase frequency in plans
- If user dislikes certain foods, avoid in future generation

### Weekly Plan Generation

**Trigger Points:**
1. First-time user (after Q1 onboarding) → Generate Week 1
2. Day before reset (notification) → Prompt for next week
3. User manually requests ("Generate Next Week's Plan" button) → Generate on demand

**Generation Logic:**

**Step 1: Calculate Targets**
- Daily calorie target (from TDEE + goal)
- Macro split:
  - Weight loss: 40% protein, 35% carbs, 25% fat
  - Weight gain: 30% protein, 45% carbs, 25% fat
  - Maintenance: 30% protein, 40% carbs, 30% fat

**Step 2: Determine Meal Count**
- Based on Q1 eating pattern (2, 3, or 4-5 meals/day)
- Meal types: Breakfast, Lunch, Dinner, Snacks (as applicable)
- Distribute calories across meals:
  - Breakfast: 25-30%
  - Lunch: 30-35%
  - Dinner: 30-35%
  - Snacks: 10-15%

**Step 3: Generate Meals**
- API call to OpenAI with constraints:
  - Calorie targets per meal
  - Macro targets per meal
  - Dietary restrictions
  - Liked/disliked foods
  - Variety (no repeats within same week)
- Generate 7 days × meal count
- Example: 7 days × 3 meals = 21 meals per week

**Step 4: Generate Workouts**
- Based on user goal and fitness level
- Frequency: 3-5 days/week (from Q1)
- Mix cardio and strength based on goal
- Equipment: Matches user's available equipment
- Rest days: Distributed throughout week

**Step 5: Compile Grocery List**
- Aggregate all ingredients from week's meals
- Group by category (proteins, vegetables, grains, etc.)
- Calculate total quantities needed
- Remove pantry staples user already has

**Processing Time:** 10-15 seconds

**Caching:** Plans cached for 7 days (until reset)

### Logging Logic

**Planned Meal Logging:**
1. User taps checkbox on planned meal
2. Meal marked as "logged" with timestamp
3. Calories/macros added to daily totals
4. Progress circles update
5. Streak logic checks (see below)

**Custom Meal Logging:**
1. User logs via AI flow
2. Item added to today's meal list (or replaced existing)
3. Badge "Logged" added to distinguish from planned
4. Calories/macros added to daily totals
5. If replacement: Original planned meal calories subtracted

**Workout Logging:**
- Same logic as meals
- Time added to daily exercise total
- Calories burned added to total

**Weight Logging:**
1. Entry saved with date
2. Progress graph updates
3. Trend line recalculated
4. % toward goal updated
5. Status (on track/ahead/behind) recalculated

### Streak Logic

**Day Completion Criteria:**
- **Acceptable variance:** 80-120% of calorie target met
- **OR:** All planned meals logged (regardless of custom additions)
- **OR:** User manually marks day complete (future feature)

**Streak Increment:**
- Checks daily at midnight (user's timezone)
- If previous day met criteria → Increment streak
- If previous day did not meet criteria → Reset streak to 0

**Timezone Handling:**
- Streak calculated based on user's device local timezone (adjusts with travel)
- "Day" defined as midnight-to-midnight in current timezone
- **Edge case:** If user crosses multiple timezones in single day, streak evaluation uses timezone where app was last opened at midnight
- Prevents unfair streak breaks due to travel

**Streak Persistence:**
- Stored in user profile
- Historical streaks saved (for "Longest Streak" stat)

### Favorite/Dislike Tracking

**Favorite:**
- Adds meal/workout to "Saved" library
- Increases weight in future generation algorithm
- More likely to appear in future plans

**Dislike:**
- Marks meal/workout as avoided
- Decreases weight in future generation algorithm
- Less likely to appear in future plans (not completely removed)

**Storage:**
- User profile: `favorites: [meal_ids]`, `dislikes: [meal_ids]`
- Used in AI prompt for personalization

### Data Sync & Offline

**Real-Time Sync:**
- All logging actions sync immediately (if online)
- Progress updates reflected across all views instantly

**Cross-Tab State Management:**
- All tabs (Home, Log, Progress) share single source of truth (global state)
- **Example:** User logs meal via Home tab checkbox → Log tab history feed updates immediately without refresh
- **Example:** User logs weight via Log tab → Progress tab graph updates immediately
- State updates trigger re-renders in all mounted components
- No manual refresh required (pull-to-refresh available but optional)

**Offline Mode:**

**Capabilities (Available Offline):**
- ✅ View all cached meal plans, workouts, and history
- ✅ Log meals via checkbox (queued for sync)
- ✅ Log weight (queued for sync)
- ✅ Manual meal entry with serving size adjustment (queued for sync)
- ✅ View progress graphs and statistics

**Disabled Features (Require Internet):**
- ❌ AI-powered logging (requires API)
- ❌ Meal/workout swapping via AI generation (requires API)
- ❌ Weekly plan generation (requires AI)
- ❌ New workout creation via AI (requires AI)

**Offline Library Failsafe (30-Second Timeout):**
- If AI generation takes >30 seconds OR user is offline, show fallback option:
  ```
  ⏳ Your AI plan is taking some time to load

  Would you like to choose from a preset option instead?

  [Choose from Library]  [Keep Waiting]
  ```
- **Library contains:**
  - 50 pre-cached meals (common recipes across dietary preferences)
  - 50 pre-cached workouts (variety of types, durations, equipment levels)
- Library is ONLY a failsafe - system never defaults to library when AI is available
- Library selections still respect user's dietary restrictions and equipment availability

**UI Indicators:**
- Banner at top when offline: "📵 Offline - Changes will sync when connected"
- Disabled buttons show tooltip: "Requires internet connection"
- Queued items show small "⏳ Syncing..." indicator next to them

**Sync Behavior:**
- Actions queued locally (IndexedDB/AsyncStorage)
- When connection restored, sync queued items in chronological order
- User sees toast: "✓ X items synced successfully"
- Conflict resolution: Last write wins (rare edge case)

**Sync Indicator:**
- Subtle icon in header shows sync status
- "Syncing..." when uploading queued actions
- Green checkmark when fully synced
