## Overview

**What:** Comprehensive settings and user profile management system allowing users to customize app preferences, edit personal information, manage their account, view subscription status, and access support resources.

**Why:** Users need control over their experience (notifications, units, theme), ability to update their profile as their goals change, and access to account management (subscription, support, logout). This is essential for long-term app retention and user satisfaction.

**When:** Accessed via settings icon (⚙️) in top-right corner of Home tab (mentioned in Q3.0 line 110). Available at any time after onboarding completion.

**Dependencies:**
- Q1 Onboarding (source of initial user data)
- Q3.0 Navigation & App Shell (settings icon placement)
- Design System (UI components, colors, typography)
- Subscription/payment system (Stripe or RevenueCat integration)

## User Stories

### Primary User Story
**As a** WeightGPT user
**I want** to access and customize my app settings
**So that** I can personalize my experience and manage my account
**Acceptance Criteria:**
- [ ] Settings accessible via ⚙️ icon in app header
- [ ] Can view and edit profile information
- [ ] Can toggle all preference settings
- [ ] Can view subscription status and billing
- [ ] Can access support and help resources
- [ ] Can log out of the app

### Profile Editing Story
**As a** user whose weight or goals have changed
**I want** to update my profile information
**So that** my meal and workout plans remain accurate
**Acceptance Criteria:**
- [ ] Can edit current weight anytime
- [ ] Can edit goal weight and goal date
- [ ] Can change dietary preferences and restrictions
- [ ] Can update fitness level and equipment
- [ ] Can modify eating pattern and meal preferences
- [ ] Changes trigger plan regeneration if significant

### Preference Customization Story
**As a** user with specific preferences
**I want** to customize app behavior
**So that** the app works the way I prefer
**Acceptance Criteria:**
- [ ] Can toggle notifications on/off
- [ ] Can change units (lbs/kg, inches/cm)
- [ ] Can change theme (light/dark)
- [ ] Can change weekly reset day (Monday/Sunday)
- [ ] Preferences persist across sessions
- [ ] Changes take effect immediately

### Account Management Story
**As a** subscriber
**I want** to view and manage my subscription
**So that** I can update billing or cancel if needed
**Acceptance Criteria:**
- [ ] Can view subscription status (active, trial, expired)
- [ ] Can see next billing date and amount
- [ ] Can update payment method
- [ ] Can cancel subscription
- [ ] Can restore purchases (iOS)
- [ ] Can request refund or contact billing support

### Support Access Story
**As a** user who needs help
**I want** to access support resources
**So that** I can get answers or report issues
**Acceptance Criteria:**
- [ ] Can access FAQ/Help Center
- [ ] Can contact support via email
- [ ] Can report a bug
- [ ] Can request a feature
- [ ] Can view app version and privacy policy

### Regeneration Triggers *(Updated Session 23 - Gap 4)*

**Meal Plan Regeneration (triggered when):**
- Goal type changed (lose/gain/maintain)
- Goal weight changed by >10 lbs
- Dietary restrictions modified
- Eating pattern modified (meals per day, meal types, snacks)
- Avoided foods modified

**Workout Plan Regeneration (triggered when):**
- Goal type changed (affects cardio/strength split)
- Fitness level changed
- Available equipment modified

**Calorie/Macro Recalculation (triggered when):**
- Current weight updated
- Activity level changed
- Goal weight changed
- Goal date changed

**Important Rules (Gap 4 Resolution):**
- ✅ Settings-triggered regenerations **DON'T count** toward 5/week regeneration limit (unlimited)
- ✅ Logged days preserved unchanged, only future days regenerated
- ✅ 30-second debounce for multiple quick changes (batch them into single regeneration)
- ✅ 24-hour backup of old plan for undo capability

**Regeneration Flow:**
1. User makes change → Validation passes → 30-second debounce timer starts
2. If no additional changes within 30 seconds → Show confirmation modal:
   ```
   ┌─────────────────────────────────────┐
   │  Regenerate Your Plans?             │
   ├─────────────────────────────────────┤
   │  Changing [field] will regenerate   │
   │  your [meal plan/workout plan/both].│
   │                                     │
   │  What will be regenerated:          │
   │  ✓ Future days (starting tomorrow)  │
   │  ✓ Any unlogged meals/workouts      │
   │                                     │
   │  What will be preserved:            │
   │  ✓ Logged meals/workouts            │
   │  ✓ Check-ins and progress data      │
   │  ✓ Favorites and saved items        │
   │                                     │
   │  Note: This doesn't count toward    │
   │  your weekly regeneration limit.    │
   │                                     │
   │  [Cancel]  [Regenerate]             │
   └─────────────────────────────────────┘
   ```
3. If user taps [Cancel] → Revert changes, return to Profile screen
4. If user taps [Regenerate]:
   a. Create 24-hour backup of current plans (for undo)
   b. Show loading screen (30-60 seconds) with progress indicator
   c. AI generates new plans (same flow as Q1/Q2)
   d. Apply to database:
      - **Logged days (past + today with logs):** PRESERVED unchanged
      - **Future days (tomorrow onward):** REPLACED with new plan
      - **Today (if no logs yet):** REPLACED with new plan
   e. Success → Show confirmation toast with undo option:
      ```
      ┌─────────────────────────────────────┐
      │ ✓ Plans updated based on your new  │
      │   preferences                       │
      │                        [Undo]       │
      └─────────────────────────────────────┘
      ```
   f. Navigate back to Home tab automatically
5. If error during regeneration → Show error modal:
   ```
   ┌─────────────────────────────────────┐
   │  Regeneration Failed                │
   ├─────────────────────────────────────┤
   │  We couldn't regenerate your plans. │
   │  Your settings have been saved, but │
   │  you're still using your old plan.  │
   │                                     │
   │  Try manually regenerating from the │
   │  Weekly Planning screen, or contact │
   │  support if this persists.          │
   │                                     │
   │  [Dismiss]                          │
   └─────────────────────────────────────┘
   ```

**Debouncing Logic (Gap 4):**
```javascript
// Pseudocode for batching multiple changes
let debounceTimer = null;
let pendingChanges = [];

function onSettingChanged(field, value) {
  pendingChanges.push({ field, value });

  clearTimeout(debounceTimer);

  debounceTimer = setTimeout(() => {
    // 30 seconds passed, batch all pending changes
    const affectsPlans = pendingChanges.some(change =>
      requiresRegeneration(change.field)
    );

    if (affectsPlans) {
      showRegenerationModal(pendingChanges);
    } else {
      savePendingChanges();
    }

    pendingChanges = [];
  }, 30000); // 30 seconds
}
```

**Undo Capability (Gap 4):**
- Backup stored for 24 hours after regeneration
- [Undo] button available in success toast for 10 seconds
- Tapping [Undo] restores previous plan completely
- After 24 hours, backup auto-deleted
- Database: Store backup in `plan_backups` table with TTL
