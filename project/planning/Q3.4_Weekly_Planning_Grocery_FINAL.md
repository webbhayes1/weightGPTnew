## Overview

**What:** AI-powered weekly meal plan and workout plan generation system with automatic grocery list creation. Generates balanced, varied, personalized plans that respect user preferences, distribute macros evenly across days, reuse ingredients efficiently, and include shopping lists organized by store section.

**Why:** Weekly planning is the core value proposition of WeightGPT. Users need automated meal and workout generation that removes the mental burden of planning while ensuring nutritional balance and variety. Grocery lists make meal execution frictionless. This is what users pay for - intelligent, personalized weekly planning.

**When:** Generated automatically after onboarding/subscription, regenerated weekly (prompted on shopping day), manually regenerable anytime. Used by 100% of active users.

**Dependencies:**
- Q1 Onboarding (user profile, dietary preferences, eating pattern, workout frequency)
- Q2 Meal Planning (meal structure, recipes)
- Q3.0 Navigation (Weekly View screen, Home tab)
- Q3.2 AI Logging (OpenAI integration patterns)
- Q3.3 Swapping (swap affects plan, regeneration needed)
- Q0 Data Structures (MealPlan, WorkoutPlan, GroceryItem interfaces)

## User Stories

### Primary User Story: Automatic Weekly Generation
**As a** newly subscribed user
**I want** my first week's meal and workout plans to generate automatically
**So that** I can immediately start using the app without manual setup
**Acceptance Criteria:**
- [ ] Plan generates in background on first app open after subscription
- [ ] Loading screen shows progress: "Creating your personalized plan..."
- [ ] Generation completes in 15-20 seconds
- [ ] Generates 7 days of meals (based on eating pattern from Q1)
- [ ] Generates workouts matching frequency from Q1 (e.g., 3 workouts for 3×/week)
- [ ] All meals respect dietary restrictions and avoided foods
- [ ] Meals distributed evenly across days (±5% calorie variance)
- [ ] Grocery list auto-generated after meal plan
- [ ] User sees "Your plan is ready!" confirmation

### Weekly Regeneration Story
**As a** user approaching the end of my week
**I want** to be prompted to generate next week's plan
**So that** I always have fresh meals and workouts planned
**Acceptance Criteria:**
- [ ] Notification sent on user's shopping day (from Q3.1 preferences)
- [ ] Notification message: "It's Sunday - time to plan next week! 🛒"
- [ ] Tap notification → Opens regeneration prompt
- [ ] Shows favorited meals from last week with checkboxes
- [ ] Option to include favorites or generate all new meals
- [ ] Generates new plan in <20 seconds
- [ ] New plan starts on next Monday (week_start_date)
- [ ] Old plan moves to "past" status

### Manual Regeneration Story
**As a** user who wants to change my entire week
**I want** to manually regenerate my meal plan
**So that** I can get new meal options if I don't like current ones
**Acceptance Criteria:**
- [ ] Accessible from Weekly View: [Regenerate Plan] button
- [ ] Confirmation prompt: "This will replace your entire meal plan. Continue?"
- [ ] Option to keep favorites (checkboxes for favorited meals)
- [ ] Loading screen during generation
- [ ] New plan respects same constraints (dietary, macros, variety)
- [ ] Grocery list regenerates with new plan
- [ ] Regeneration count tracked (limit 5 per week to prevent API abuse)

### Grocery List Generation Story
**As a** user preparing to grocery shop
**I want** an organized shopping list for the week
**So that** I can efficiently buy everything I need
**Acceptance Criteria:**
- [ ] Automatically generated after meal plan creation
- [ ] Ingredients consolidated across entire week ("Chicken breast: 3 lbs" not "6 chicken breasts")
- [ ] Organized by store section (Proteins, Produce, Dairy/Eggs, Pantry, Spices, Frozen, Bakery, Other)
- [ ] Checkboxes to mark items as purchased/already-have
- [ ] Can add custom items manually
- [ ] Can remove items I don't need
- [ ] Can export as PDF, plain text, or image
- [ ] Can share via SMS, email, or AirDrop

### Favorites Integration Story
**As a** user who loved certain meals
**I want** my favorited meals to appear in future weeks
**So that** I can enjoy meals I love without searching
**Acceptance Criteria:**
- [ ] Favorited meals (from Q3.0 heart icon) stored in user profile
- [ ] Regeneration prompt shows favorited meals with checkboxes
- [ ] Selected favorites included in new week (replaces AI-generated meals)
- [ ] Favorites still respect macro targets (won't include if breaks daily totals)
- [ ] Maximum 2-3 favorites per week (prevents repetition)

## User Flow

### First-Time Weekly Plan Generation

**Entry Points:**
1. Welcome modal on first app open (user taps [Generate My Plan])
2. Empty state CTA buttons (Home tab, [Generate My Plan])
3. Persistent banner (user taps [Generate Now →])
4. Floating action button (FAB) on any tab

**Flow:**

```
User taps any "Generate Plan" CTA
    ↓
┌─────────────────────────────────────────────────────────┐
│              Creating Your Plan                         │
│                                                         │
│         [Animated loading indicator]                    │
│                                                         │

    ↓
Backend Process:
1. Fetch user profile (goals, macros, preferences, eating pattern)
2. Call OpenAI API to generate 14-28 meals (7 days × 2-4 meals/day)
3. Generate workouts matching frequency (e.g., 3 workouts for 3×/week)
4. Consolidate ingredients → Create grocery list
5. Save to database (MealPlan, WorkoutPlan, GroceryList)
6. Update user state: first_plan_generated = true
    ↓
┌─────────────────────────────────────────────────────────┐
│              Your Plan is Ready! 🎉                     │
│                                                         │
│  Week of Nov 4-10                                       │
│                                                         │

│  • 3 custom workouts                                   │
│  • Shopping list with 45 items                         │
│                                                         │
│  [View My Week]                                         │
└─────────────────────────────────────────────────────────┘
    ↓
Tap [View My Week]
    ↓
Home Tab refreshes with full plan:
- Persistent banner dismisses automatically
- Floating action button (FAB) disappears
- Progress circles show planned meals
- Today's meals section populated
- User can view/log/swap meals
    ↓
User can:
- View all meals/workouts
- Swap individual items (Q3.3)
- View/export grocery list
- Quick-log items
- Access all AI features
```

```
**User Interactions (Gap 10 - Session 23 Enhanced):**

**1. Checking Off Items:**
- Tap checkbox: ☐ → ☑ (checked state)
- **Visual changes:**
  - Strikethrough text style
  - 50% opacity (grayed out)
  - Checkbox filled with green #4BAE90
- **Can toggle:** Tap again → ☑ → ☐ (uncheck)
- **Editable quantity:** Tap quantity → Number picker → Update (e.g., "3 lbs" → "2 lbs")
- **Persistence:** Checked state persists within current week
  - Resets when new week generated (all items unchecked)
  - Survives app restarts during same week

**2. Adding Custom Items:**
- Tap [+ Add Item] button
- Modal opens: "Add to Shopping List"
  - Text input: Item name (required)
  - Text input: Quantity (optional, default "1")
  - Dropdown: Category selection (auto-categorizes)
  - Buttons: [Cancel] [Add]
- **Persistence:** Custom items persist until manually deleted
  - NOT removed on weekly reset (user's personal additions)
  - Carry over to next week if not deleted

**3. Swap Impact on Grocery List (Gap 10):**
- **Scenario:** User swaps meal that contains unique ingredient
- **Behavior:**
  - Ingredient removed from meal plan
  - **Toast notification:** "Grilled Chicken Salad swapped. Shopping list updated."
  - **Orphaned items** (ingredients no longer needed):
    - Grayed out with 50% opacity
    - Badge appears: "No longer needed" (light gray pill)
    - User can still check/uncheck (in case they want ingredient anyway)
    - User can delete manually (swipe left → Delete)
- **Example:**
  - Original: Monday lunch has "Grilled Chicken Salad" → Grocery list has "Chicken breast • 3 lbs"
  - User swaps to "Salmon Bowl"
  - Chicken breast quantity reduces: "3 lbs" → "2 lbs" (other meals still use chicken)
  - If no other meals use chicken → "No longer needed" badge appears

**4. Removing Items:**
- Swipe left on any item → [Delete] button appears
- Tap [Delete] → Item removed from list
- Can delete both auto-generated and custom items
- No undo (permanent deletion)

**5. Exporting List:**
- Tap [Export] button → Bottom sheet modal:
  - [Export as PDF] → Generates PDF, opens share sheet
  - [Copy as Text] → Copies plain text to clipboard
  - [Share as Image] → Generates image, opens share sheet
  - [Send to Reminders] → Creates Apple Reminders checklist (iOS only)
```

#### 2. Grocery List Consolidation Algorithm

**Purpose:** Convert meal ingredients into consolidated shopping list organized by store section

**Input:**
- Meal plan with all meals
- Each meal has ingredients array

**Process:**

```typescript
function consolidateGroceryList(meals: Meal[]): GroceryItem[] {
  // 1. Extract all ingredients from all meals
  const allIngredients: Ingredient[] = meals.flatMap(meal => meal.ingredients);

  // 2. Group by ingredient name (case-insensitive)
  const grouped: Map<string, Ingredient[]> = new Map();

  allIngredients.forEach(ingredient => {
    const normalizedName = ingredient.name.toLowerCase().trim();
    if (!grouped.has(normalizedName)) {
      grouped.set(normalizedName, []);
    }
    grouped.get(normalizedName)!.push(ingredient);
  });

  // 3. Sum quantities for each ingredient (convert to user-friendly units)
  const consolidatedItems: GroceryItem[] = [];

  grouped.forEach((ingredients, name) => {
    const category = ingredients[0].category;

    // Determine best unit for this ingredient category
    const targetUnit = determineTargetUnit(category, ingredients);

    // Convert all quantities to target unit and sum
    let totalQuantity = 0;
    ingredients.forEach(ing => {
      const converted = convertToUnit(ing.quantity, ing.unit, targetUnit);
      totalQuantity += converted;
    });

    // Round to reasonable precision
    totalQuantity = roundQuantity(totalQuantity, targetUnit);

    consolidatedItems.push({
      item: capitalizeFirstLetter(name),
      quantity: totalQuantity,
      unit: targetUnit,
      category: category,
      purchased: false,
    });
  });

  // 4. Sort by category (store section order)
  const categoryOrder = ['proteins', 'produce', 'dairy-eggs', 'pantry', 'spices', 'frozen', 'bakery', 'other'];

  consolidatedItems.sort((a, b) => {
    const aIndex = categoryOrder.indexOf(a.category);
    const bIndex = categoryOrder.indexOf(b.category);
    return aIndex - bIndex;
  });

  return consolidatedItems;
}

function determineTargetUnit(category: string, ingredients: Ingredient[]): string {
  // Choose user-friendly unit based on category
  // NEVER use 'oz' - always convert to lb, count, or cup

  if (category === 'proteins' || category === 'produce') {
    return 'lb'; // Always pounds for proteins and produce
  } else if (category === 'dairy-eggs') {
    // Use most common unit (cup for liquids, count for eggs, lb for cheese)
    const hasCount = ingredients.some(ing => ing.unit === 'count');
    return hasCount ? 'count' : 'cup';
  } else if (category === 'spices' || category === 'pantry') {
    // Use smallest unit present (tsp < tbsp < cup)
    const units = ingredients.map(ing => ing.unit);
    if (units.includes('tsp')) return 'tsp';
    if (units.includes('tbsp')) return 'tbsp';
    return 'cup';
  } else {
    return ingredients[0].unit; // Default to first unit
  }
}

function convertToUnit(quantity: number, fromUnit: string, toUnit: string): number {
  // Handle same unit
  if (fromUnit === toUnit) return quantity;

  // Weight conversions (oz → lb ONLY, never display oz)
  if (fromUnit === 'oz' && toUnit === 'lb') {
    return quantity / 16;
  }
  if (fromUnit === 'lb' && toUnit === 'oz') {
    // This should never happen (we never target oz), but handle gracefully
    return quantity * 16;
  }

  // Volume conversions
  if (fromUnit === 'tsp' && toUnit === 'tbsp') return quantity / 3;
  if (fromUnit === 'tbsp' && toUnit === 'tsp') return quantity * 3;
  if (fromUnit === 'tbsp' && toUnit === 'cup') return quantity / 16;
  if (fromUnit === 'cup' && toUnit === 'tbsp') return quantity * 16;
  if (fromUnit === 'tsp' && toUnit === 'cup') return quantity / 48;
  if (fromUnit === 'cup' && toUnit === 'tsp') return quantity * 48;

  // If no conversion available, return original (shouldn't happen with proper AI prompts)
  console.warn(`No conversion from ${fromUnit} to ${toUnit}`);
  return quantity;
}

function roundQuantity(quantity: number, unit: string): number {
  // Round to reasonable precision based on unit
  switch (unit) {
    case 'lb':
      return Math.round(quantity * 10) / 10; // 1 decimal place (e.g., 1.3 lbs)
    case 'count':
      return Math.ceil(quantity); // Always round up for count
    case 'cup':
      return Math.round(quantity * 4) / 4; // Quarter increments (e.g., 1.25 cups)
    case 'tbsp':
    case 'tsp':
      return Math.round(quantity * 2) / 2; // Half increments (e.g., 2.5 tsp)
    case 'package':
      return Math.ceil(quantity);
    default:
      return Math.round(quantity * 10) / 10;
  }
}
```

```typescript
async function generateWeeklyWorkoutPlan(
  userProfile: UserProfile,
  weekStartDate: Date
): Promise<WorkoutPlan> {

  const frequency = userProfile.workout_frequency; // e.g., 3 days/week
  const fitnessLevel = userProfile.fitness_level;
  const goal = userProfile.goal;
  const equipment = userProfile.available_equipment;

  // 1. Determine workout split based on goal
  let workoutSplit: string[];

  if (goal === 'lose_weight') {
    // More cardio-focused (60% cardio, 40% strength)
    workoutSplit = frequency === 3
      ? ['cardio', 'strength', 'cardio']
      : frequency === 4
      ? ['cardio', 'strength', 'cardio', 'strength']
      : ['cardio', 'strength', 'cardio', 'strength', 'cardio'];
  } else if (goal === 'gain_weight') {
    // More strength-focused (70% strength, 30% cardio)
    workoutSplit = frequency === 3
      ? ['strength', 'strength', 'cardio']
      : frequency === 4
      ? ['strength', 'strength', 'cardio', 'strength']
      : ['strength', 'strength', 'cardio', 'strength', 'strength'];
  } else {
    // Balanced (50/50)
    workoutSplit = frequency === 3
      ? ['strength', 'cardio', 'strength']
      : frequency === 4
      ? ['strength', 'cardio', 'strength', 'cardio']
      : ['strength', 'cardio', 'strength', 'cardio', 'strength'];
  }

  // 2. Assign workouts to specific days (spread evenly)
  const workoutDays = spreadWorkoutsAcrossWeek(frequency); // e.g., [0, 2, 4] for Mon/Wed/Fri

  // 3. Generate each workout via OpenAI
  const workouts: Workout[] = [];

  for (let i = 0; i < workoutSplit.length; i++) {
    const type = workoutSplit[i];
    const dayOfWeek = workoutDays[i];

    const aiPrompt = `
      Generate a ${type} workout.

      USER PROFILE:
      - Fitness Level: ${fitnessLevel}
      - Goal: ${goal}
      - Equipment: ${equipment.join(', ')}

      CONSTRAINTS:
      - Duration: 30-45 minutes
      - Appropriate for ${fitnessLevel} level
      - Use only available equipment
      ${type === 'strength' ? `- Include compound exercises
      - 6-8 exercises with sets/reps` : `- Include warm-up and cool-down
      - Specify intensity (light/moderate/vigorous)`}

      OUTPUT FORMAT: JSON with workout details and exercises.
    `;

    const workout = await generateWorkoutWithOpenAI(aiPrompt);
    workout.day_of_week = dayOfWeek;
    workouts.push(workout);
  }

  // 4. Create WorkoutPlan object
  const workoutPlan: WorkoutPlan = {
    id: generateId(),
    user_id: userProfile.id,
    week_start_date: weekStartDate,
    week_end_date: addDays(weekStartDate, 6),
    status: 'active',
    workouts: workouts,
    generated_at: new Date(),
  };

  return workoutPlan;
}

function spreadWorkoutsAcrossWeek(frequency: number): number[] {
  // Spread workouts evenly across week
  // Avoid consecutive days (allow 1 rest day between)

  const schedules = {
    3: [0, 2, 4], // Mon, Wed, Fri
    4: [0, 2, 3, 5], // Mon, Wed, Thu, Sat
    5: [0, 1, 3, 4, 6], // Mon, Tue, Thu, Fri, Sun
    6: [0, 1, 2, 4, 5, 6], // Mon-Wed, Fri-Sun
    7: [0, 1, 2, 3, 4, 5, 6], // Every day
  };

  return schedules[frequency] || [0, 2, 4]; // Default to 3×/week
}
```

- **Weight Loss:** 60% cardio, 40% strength
- **Muscle Gain:** 70% strength, 30% cardio
- **Maintenance:** 50/50 split
- **Rest Days:** Automatically assigned (non-workout days)
- **Consecutive Limit:** Avoid 4+ consecutive workout days

### Validation Rules

#### Meal Plan Validation

1. **Daily Calorie Variance:**
   - Each day's total calories must be within ±5% of target
   - Validation: `Math.abs((dayTotal - target) / target) <= 0.05`
   - Error: "Day X totals are outside ±5% range (${dayTotal} vs ${target} target)"

2. **Macro Targets:**
   - Protein: ±10% of daily target
   - Carbs/Fat: Flexible (AI balances to hit calorie target)
   - Validation: Check protein specifically

3. **Variety Enforcement:**
   - No meal repeated more than once per week
   - Validation: Check for duplicate meal names (case-insensitive)
   - Error: "Duplicate meal found: ${mealName}"

4. **Dietary Restrictions:**
   - All ingredients checked against dietary_restrictions list
   - All ingredients checked against avoided_foods list
   - Validation: No overlap between ingredients and restrictions
   - Error: "Meal contains restricted ingredient: ${ingredient}"

5. **Eating Pattern Compliance:**
   - Meals generated must match meal_pattern from Q1
   - If user eats 3 meals/day → No snacks generated
   - Validation: Check meal_type matches user's pattern

#### Workout Plan Validation

1. **Frequency Match:**
   - Number of workouts must equal workout_frequency from profile
   - Validation: `workouts.length === userProfile.workout_frequency`

2. **Equipment Availability:**
   - All exercises must use only available equipment
   - Exception: Bodyweight always allowed
   - Validation: Check exercise.equipment against userProfile.available_equipment

3. **Consecutive Workout Limit:**
   - No more than 3 consecutive workout days (prevents overtraining)
   - Validation: Check day_of_week assignments
   - Warning: "4+ consecutive workout days detected. Consider adding rest day."

#### Grocery List Validation

1. **Quantity Rounding:**
   - Quantities rounded to reasonable precision (see algorithm)
   - Validation: No fractional counts (e.g., "2.5 eggs" → "3 eggs")

2. **Unit Consistency:**
   - Items with same name must have same unit for consolidation
   - If units differ → Keep separate entries with note
   - Example: "Chicken breast (6 oz pieces)" vs "Chicken breast (ground)"

### Edge Cases

**1. User regenerates 5 times in one week (Gap 6 - Session 23)**
- **Scenario:** User keeps regenerating, unhappy with plans
- **Behavior:** After 5th standard regeneration → Show limit message with emergency option:
  ```
  ┌─────────────────────────────────────┐
  │  Weekly Regeneration Limit          │
  ├─────────────────────────────────────┤
  │  You've used all 5 regenerations    │
  │  this week.                         │
  │                                     │
  │  Alternative options:               │
  │  ✓ Swap individual meals/workouts   │
  │  ✓ Add custom meals                 │
  │  ✓ Add from saved favorites         │
  │                                     │
  │  ─────────────────────────────      │
  │                                     │
  │  Need a fresh start?                │
  │                                     │
  │  [Use Emergency Regeneration]       │
  │  (1 remaining this week)            │
  │                                     │
  │  [OK] [Contact Support]             │
  └─────────────────────────────────────┘
  ```
- **Emergency Regeneration (Gap 6):**
  - User has 1 free emergency regeneration per week (6 total including 5 standard)
  - **If tapped:** Trigger full plan regeneration (same flow as standard)
  - **After emergency used:** Show: "You've used your emergency regeneration (6/6 this week). Limit resets Monday 12:00 AM."
  - **UI Proactive Warning:** Show "4 regenerations left" badge on Regenerate button when user hits 4/5
  - **Limit Reset:** Every Monday 12:00 AM (user's timezone)
  - **Alternative Actions (Always Unlimited):**
    - Swapping individual meals/workouts
    - Adding custom meals
    - Adding from favorites
    - All other non-regeneration actions

**2. Favorites exceed weekly meal count**
- **Scenario:** User selects 5 favorites, but week only has room for 3
- **Behavior:** Auto-select top 3 (most liked), gray out remaining checkboxes
- **Message:** "Maximum 3 favorites per week. Your top favorites have been selected."

**3. AI generation fails after 30s timeout**
- **Scenario:** OpenAI API slow or errors
- **Behavior:** Retry once automatically → If still fails → Error: "We're having trouble generating your plan. Please try again in a few minutes."
- **Buttons:** [Try Again] [Contact Support]

**4. User has no favorited meals for regeneration**
- **Scenario:** New user, first regeneration, no favorites yet
- **Behavior:** Skip favorites section, show: "No favorites yet! Favorite meals you love by tapping the heart icon."

**5. Grocery list empty (all items deleted)**
- **Scenario:** User deletes all items
- **Behavior:** Show empty state: "Your shopping list is empty. [+ Add Item] or [Regenerate Plan]"

**6. User tries to regenerate during generation**
- **Scenario:** User taps Regenerate while plan still generating
- **Behavior:** Disable button, show: "Generation in progress... (~15s remaining)"

**7. Dietary restrictions change mid-week**
- **Scenario:** User updates dietary preferences in Settings (Q3.1)
- **Behavior:** Prompt: "Your dietary preferences changed. Regenerate meal plan to apply changes?"
- **Buttons:** [Regenerate Now] [Apply Next Week]

**8. User has 7 favorited meals (full week)**
- **Scenario:** User wants entire week to be favorites
- **Behavior:** Allow (no AI generation needed), but warn: "Using all favorites means no variety this week. Consider selecting fewer for better balance."
