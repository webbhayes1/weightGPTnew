## Overview

**What:** Complete history and favorites management system. History screen provides paginated archive of all logged items (meals, workouts, weight) with search, filter, edit, and delete capabilities. Saved screen provides organized library of favorited meals and workouts with quick-add functionality.

**Why:** Users need to:
- Review past behavior and identify patterns
- Edit or delete incorrect historical entries
- Search for specific past meals/workouts
- Quickly re-log favorite items without AI parsing
- Access their personal library of trusted meals/workouts
- Export historical data for personal records

**When:** Accessed from Progress tab via dedicated buttons. History used weekly for review/editing. Saved used daily for quick-logging favorite items (reduces AI API costs by 60% for repeat meals).

**Dependencies:**
- Q3.0 Navigation & App Shell (Progress tab structure, basic History/Saved concepts)
- Q3.2 AI Logging (LoggedMeal, LoggedWorkout data structures)
- Q3.3 Swapping (favorites system integration)
- Q3.4 Weekly Planning (favorites in regeneration)
- Q3.5 Progress Analytics (export functionality reference)
- Q0 Data Structures (all entity interfaces)

## User Stories

### Primary User Story: History Archive Review
**As a** user tracking my progress over weeks
**I want** to view all my past logged meals, workouts, and weight entries
**So that** I can identify patterns, review adherence, and track my journey
**Acceptance Criteria:**
- [ ] Can view all historical entries paginated by week
- [ ] Can filter by type (All, Meals, Workouts, Weight)
- [ ] Can search by name/keyword
- [ ] Can jump to specific date via calendar picker
- [ ] Can drill down to day details
- [ ] Can swipe between weeks
- [ ] Empty weeks show "No activity this week" state

### Edit Historical Entry Story
**As a** user who logged incorrect information
**I want** to edit or delete past entries
**So that** my historical data remains accurate
**Acceptance Criteria:**
- [ ] Can tap entry to view details
- [ ] Can edit calories, macros, name, date
- [ ] Can delete entry with confirmation
- [ ] Changes sync immediately
- [ ] Toast confirmation: "Entry updated ✓"
- [ ] Deleted items cannot be recovered (permanent)

### Search History Story
**As a** user looking for a specific past meal
**I want** to search my history by name or date
**So that** I can quickly find and re-log items
**Acceptance Criteria:**
- [ ] Search bar filters results in real-time
- [ ] Searches across meal names, workout names
- [ ] Shows matching results with highlighting
- [ ] Can search within filtered type (e.g., "Meals" only)
- [ ] Clear search button (X icon)

### Favorites Library Story
**As a** user with favorite meals and workouts
**I want** an organized library of saved items
**So that** I can quickly log them without AI parsing
**Acceptance Criteria:**
- [ ] Can view all favorited meals categorized by meal type
- [ ] Can view all favorited workouts categorized by type
- [ ] Can search saved items
- [ ] Can quick-add to today from favorites
- [ ] Can view full details and recipe
- [ ] Can unfavorite items
- [ ] Empty state shows instructions

### Quick-Add from Favorites Story
**As a** user eating a favorite meal again
**I want** to add it to today with one tap
**So that** I can log without typing or AI processing
**Acceptance Criteria:**
- [ ] "Add to Today" button visible on each saved item
- [ ] Tap → Modal appears to select meal type and add/replace
- [ ] Confirms with toast: "Added to today! ✓"
- [ ] Home tab updates immediately
- [ ] Logged entry preserves original calories/macros
- [ ] Timestamp set to current time

### Export History Story
**As a** user wanting to analyze data externally
**I want** to export my history
**So that** I can review in spreadsheets or share with dietitian
**Acceptance Criteria:**
- [ ] Export button in History screen
- [ ] Can select date range (week, month, all-time)
- [ ] Exports as CSV file
- [ ] Includes all fields (date, name, calories, macros, type)
- [ ] Generates file and triggers share sheet
- [ ] File naming: "WeightGPT_History_YYYY-MM-DD.csv"


**Components:**

**Back Button (←):**
- Left side

**Search Icon (🔍):**
- Top right

### 2. Filter Tabs

```
┌─────────────────────────────────────┐
│ [All] [Meals] [Workouts] [Weight]   │
└─────────────────────────────────────┘
```

**Tab Behavior:**
- 4 tabs: All, Meals, Workouts, Weight

**Filter Logic:**
- **All:** Shows meals, workouts, weight entries
- **Meals:** Shows only logged meals
- **Workouts:** Shows only logged workouts
- **Weight:** Shows only weight log entries

### 3. Search Bar (Expandable)

```
┌─────────────────────────────────────┐
│ 🔍 Search history...             ✕  │
└─────────────────────────────────────┘
```

**Behavior:**
- Hidden by default
- Tap search icon → Expands with slide-down animation
- Auto-focuses keyboard
- Real-time filtering as user types
- Searches: meal names, workout names
- Case-insensitive
- Highlights matching text in results
- Clear button (✕) on right clears input and collapses bar

**Search Algorithm:**
- Searches across `name` field in LoggedEntry
- Supports partial matches (e.g., "chick" matches "Grilled Chicken")
- Results ranked by relevance (exact match > starts with > contains)

**Next Week Arrow (→):**

**Swipe Entry (Left Swipe):**
- Quick actions revealed:
  ```
  [✏️ Edit] [❤️ Favorite] [🗑️ Delete]
  ```
- Actions:
  - **Edit:** Opens edit modal
  - **Favorite:** Adds to Saved (heart fills, toast: "Added to favorites ✓")
  - **Delete:** Shows confirmation dialog

**Long-Press Entry:**
- Context menu appears:
  ```
  Edit
  Add to Favorites / Remove from Favorites
  Delete
  Duplicate (add to today)
  Share
  ```

**Delete Confirmation:**
```
┌─────────────────────────────────────┐
```

- White card centered
- Cancel (gray) vs Delete (red) buttons
- Tap Delete → Entry removed, toast: "Entry deleted"
- Undo NOT available (permanent deletion)

### 7. Week Pagination Behavior

**Loading:**
- Initial load: Current week (Monday-Sunday containing today)
- Loads 1 week at a time
- Skeleton loading state while fetching:
  ```
  ┌─────────────────────────────────────┐
  │ [Gray shimmering rectangles]        │
  │ [Gray shimmering rectangles]        │
  │ [Gray shimmering rectangles]        │
  └─────────────────────────────────────┘
  ```

**Lazy Loading:**
- Swipe to previous/next week → API call fetches that week's data
- Caches last 3 weeks in memory
- If week already cached → Instant display
- If not cached → Show loading skeleton, fetch from API

**Infinite Pagination:**
- Can scroll back to user's first logged entry
- Forward limit: Current week (cannot view future)
- Remembers scroll position when navigating away

- PDF: `WeightGPT_Report_YYYY-MM-DD.pdf`

```csv
2024-11-06,07:00,Weight,185.2,,,,,Down 0.5 lbs
```

**PDF Format:**
- Header: WeightGPT logo + "Activity Report"
- Date range
- Summary statistics (total meals, workouts, avg weight)
- Day-by-day breakdown
- Charts (weight trend, calorie average)

## Technical Requirements

### Performance Requirements

**History Screen:**
- Week load time: <800ms
- Search results: <200ms (real-time filtering)
- Infinite scroll: Pre-fetch next/previous week when user scrolls within 10% of edge
- Entry detail load: <400ms
- Export generation: <5 seconds for 90 days, <15 seconds for all-time

**Saved Screen:**
- Initial load: <500ms (all saved items fetched at once, typically <100 items)
- Search filtering: <100ms (client-side filtering)
- Add to Today: <600ms (API call + UI update)
- Category expand/collapse: Instant (client-side animation)

### Memory Constraints

**History:**
- Cache max 5 weeks in memory (rolling cache)
- Oldest week purged when 6th week loaded
- Each week ~50-100 entries max
- Total memory: ~500 entries in cache

**Saved:**
- All saved items loaded at once (typically 20-80 items)
- Max 200 saved items per user (enforced limit)
- Images lazy-loaded (only load when scrolled into view)

### Network Optimization

**History:**
- Paginated API calls (1 week per request)
- Gzip compression on JSON responses
- ETag caching (week data rarely changes)
- Offline: Show cached weeks with banner "Viewing cached data"

**Saved:**
- Single API call fetches all saved items
- Cached for 7 days (invalidate on favorite/unfavorite)
- Images CDN-cached
- Offline: Fully functional with cached data

### Data Validation

**Edit Entry Validation:**
- Calories: 10-5000 range
- Protein: 0-200g
- Carbs: 0-500g
- Fat: 0-200g
- Date: Cannot be future date, cannot be before user creation date
- Weight: 50-500 lbs (or 20-250 kg if metric)

**Delete Entry Validation:**
- Cannot delete if entry is part of active streak (show warning)
- Warning if deleting weight entry (affects progress graph)

### Error Handling

**Network Errors:**
- Week load failure → Show cached data if available + banner: "Couldn't load latest data"
- Retry button
- Export failure → Toast: "Export failed. Please try again."

**Data Errors:**
- Missing entry data → Show placeholder: "Data unavailable"
- Corrupt data → Skip entry, log error to backend
- Empty response → Show appropriate empty state

**Offline Mode:**
- History: Show cached weeks only
- Saved: Fully functional (all data cached)
- Edit/Delete: Queue action, sync when online
- Banner: "You're offline. Changes will sync when connected."

## Algorithms

### 1. Week Pagination Algorithm

**Purpose:** Determine which week to display and enable/disable navigation arrows

**Input:**
- `current_date: Date` (today or selected date)
- `user_first_entry_date: Date` (user's earliest logged entry)

**Output:**
- `week_start: Date` (Monday)
- `week_end: Date` (Sunday)
- `can_go_previous: boolean`
- `can_go_next: boolean`

**Pseudocode:**
```javascript
function getWeekForDate(date) {
  // Find Monday of week containing date
  const dayOfWeek = date.getDay(); // 0 = Sunday, 1 = Monday, etc.
  const daysToMonday = (dayOfWeek === 0) ? 6 : dayOfWeek - 1;
  const monday = new Date(date);
  monday.setDate(date.getDate() - daysToMonday);

  // Find Sunday of same week
  const sunday = new Date(monday);
  sunday.setDate(monday.getDate() + 6);

  return {
    week_start: monday,
    week_end: sunday
  };
}

function canNavigate(week_start, week_end, user_first_entry_date, today) {
  // Can go to previous week if not already at user's first week
  const user_first_week = getWeekForDate(user_first_entry_date);
  const can_go_previous = week_start > user_first_week.week_start;

  // Can go to next week if not already at current week
  const current_week = getWeekForDate(today);
  const can_go_next = week_end < current_week.week_end;

  return {
    can_go_previous,
    can_go_next
  };
}
```

**Example:**
- Today: Nov 6, 2024 (Wednesday)
- Current week: Nov 4-10 (Mon-Sun)
- User first entry: Oct 15, 2024
- User first week: Oct 14-20
- `can_go_previous`: true (can go back 2+ weeks)
- `can_go_next`: false (already at current week)

### 2. Search Ranking Algorithm

**Purpose:** Rank search results by relevance

**Input:**
- `query: string` (user search term)
- `entries: LoggedEntry[]` (all historical entries)

**Output:**
- `ranked_results: { entry: LoggedEntry, score: number }[]` (sorted by score descending)

**Scoring Rules:**
1. Exact match (case-insensitive): score = 1.0
2. Starts with query: score = 0.8
3. Contains query (word boundary): score = 0.6
4. Contains query (anywhere): score = 0.4
5. Fuzzy match (Levenshtein distance ≤ 2): score = 0.2

**Pseudocode:**
```javascript
function searchAndRank(query, entries) {
  const lowerQuery = query.toLowerCase();
  const results = [];

  for (const entry of entries) {
    let name = '';
    if (entry.type === 'meal') name = entry.meal.name;
    else if (entry.type === 'workout') name = entry.workout.name;
    else continue; // Skip weight entries (no searchable name)

    const lowerName = name.toLowerCase();
    let score = 0;

    // Exact match
    if (lowerName === lowerQuery) {
      score = 1.0;
    }
    // Starts with
    else if (lowerName.startsWith(lowerQuery)) {
      score = 0.8;
    }
    // Word boundary match
    else if (new RegExp(`\\b${lowerQuery}`, 'i').test(name)) {
      score = 0.6;
    }
    // Contains anywhere
    else if (lowerName.includes(lowerQuery)) {
      score = 0.4;
    }
    // Fuzzy match (Levenshtein distance ≤ 2)
    else if (levenshteinDistance(lowerQuery, lowerName) <= 2) {
      score = 0.2;
    }

    if (score > 0) {
      results.push({ entry, score });
    }
  }

  // Sort by score descending, then by date descending (most recent first)
  results.sort((a, b) => {
    if (a.score !== b.score) return b.score - a.score;
    return b.entry.date - a.entry.date;
  });

  return results;
}

function levenshteinDistance(a, b) {
  const matrix = [];
  for (let i = 0; i <= b.length; i++) {
    matrix[i] = [i];
  }
  for (let j = 0; j <= a.length; j++) {
    matrix[0][j] = j;
  }
  for (let i = 1; i <= b.length; i++) {
    for (let j = 1; j <= a.length; j++) {
      if (b.charAt(i - 1) === a.charAt(j - 1)) {
        matrix[i][j] = matrix[i - 1][j - 1];
      } else {
        matrix[i][j] = Math.min(
          matrix[i - 1][j - 1] + 1, // substitution
          matrix[i][j - 1] + 1,     // insertion
          matrix[i - 1][j] + 1      // deletion
        );
      }
    }
  }
  return matrix[b.length][a.length];
}
```

### 3. Export Generation Algorithm (CSV)

**Purpose:** Generate CSV file from historical entries

**Input:**
- `entries: LoggedEntry[]` (all entries in date range)
- `data_types: string[]` (meals, workouts, weight)

**Output:**
- `csv_string: string` (CSV formatted data)

**Pseudocode:**
```javascript
function generateCSV(entries, data_types) {
  // CSV header
  let csv = 'Date,Time,Type,Name,Calories,Protein (g),Carbs (g),Fat (g),Duration (min),Notes\n';

  // Filter entries by data types
  const filtered = entries.filter(entry => data_types.includes(entry.type));

  // Sort by date and time (oldest to newest)
  filtered.sort((a, b) => a.logged_at - b.logged_at);

  for (const entry of filtered) {
    const date = formatDate(entry.date, 'YYYY-MM-DD');
    const time = formatDate(entry.logged_at, 'HH:mm');

    if (entry.type === 'meal') {
      const meal = entry.meal;
      csv += `${date},${time},Meal,${escapeCsvField(meal.name)},${meal.calories},${meal.macros.protein_g},${meal.macros.carbs_g},${meal.macros.fat_g},,\n`;
    }
    else if (entry.type === 'workout') {
      const workout = entry.workout;
      csv += `${date},${time},Workout,${escapeCsvField(workout.name)},${workout.calories_burned},,,${workout.duration_min},\n`;
    }
    else if (entry.type === 'weight') {
      const weight = entry.weight;
      const notes = `${weight.change_from_last > 0 ? '+' : ''}${weight.change_from_last} lbs`;
      csv += `${date},${time},Weight,${weight.weight_lbs} lbs,,,,,${escapeCsvField(notes)}\n`;
    }
  }

  return csv;
}

function escapeCsvField(field) {
  // Escape double quotes and wrap in quotes if contains comma
  if (field.includes(',') || field.includes('"') || field.includes('\n')) {
    return `"${field.replace(/"/g, '""')}"`;
  }
  return field;
}
```

**Example Output:**

## Implementation Notes

### Phase 1: MVP
- History screen with week pagination
- Basic search (name only)
- Edit and delete entries
- Saved screen with categories
- Add to Today functionality
- CSV export only

### Phase 2: Enhancements
- Advanced search (date range, calorie range, macro filters)
- PDF export with charts
- Drag-and-drop reordering in Saved
- Custom categories/tags
- Batch operations (delete multiple, export selection)

### Phase 3: Advanced
- AI insights from history ("You tend to eat salads on Mondays")
- Recipe variations (save modified versions)
- Meal plan from favorites (generate week from saved items only)
- Social sharing (share favorite recipes with friends)

### Data Migration
- Existing `is_favorite` field in LoggedEntry → Populate SavedItem table
- One-time migration script to denormalize favorited entries
- Handle duplicates (user favorited same meal multiple times)

### Testing Priorities
1. Week pagination edge cases (first week, current week, empty weeks)
2. Search ranking accuracy (exact match, partial match, fuzzy match)
3. Edit/delete impact on daily/weekly summaries and streaks
4. Add to Today with replace (ensure old entry deleted)
5. Export file generation and download
6. Offline mode (cached weeks, queued edits)

### Known Limitations
- Max 200 saved items per user (prevent database bloat)
- Search limited to 100 results (pagination for more)
- Export limited to 2 years of data (performance constraint)
- CSV export only text data (no images)
